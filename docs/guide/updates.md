# 更新与待办

更新是被动的:应用只负责发现和呈现,落不落盘永远由你确认。

## 来源更新检查

启动时和每 30 分钟自动检查一次,也可以在 设置 → 应用更新 里手动「检查更新」:

- **本地来源**:按文件变更检测,平时有文件监听实时同步
- **GitHub 来源**:`git ls-remote` 比较远端 SHA——**只比较,绝不 pull**

为什么这么谨慎:安装是软链直连,一旦 pull,上游删改的文件会立即传导到每个 Agent。所以「更新」必须是你在前端确认后的显式动作。

## 更新预览

「待办」页或来源页的更新入口点开后,是 git diff 级别的预览:哪些文件加了、改了、删了,一目了然。确认后才应用更新。

## 待办页

左栏「待办」的计数只统计真正需要处理的事:

- 失效或冲突的软链(比如目标被手动删了)
- 有更新的来源
- 启用了但未检测到本机安装的 Agent

处理完一项,计数就少一项;清零说明一切正常。
