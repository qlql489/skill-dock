# 数据目录与安全模型

## 数据放在哪

新安装的应用状态都在 `~/.skill-dock/`。从 Skill Manager 升级时，SkillDock 会继续读取已有的 `~/.skill-manager/`，避免移动文件造成配置丢失：

```
~/.skill-dock/
├── state.json      # 来源、Agent、安装关系、组合配置
└── repos/<uuid>/   # GitHub 来源的本地克隆
```

技能本体永远留在来源目录(你的文件夹、克隆的仓库、市场下载的目录),`state.json` 只记录索引和软链关系。删掉 SkillDock,技能文件原封不动。

## 安装的安全规则

安装走符号链接,而符号链接的所有权有严格模型:

- **SkillDock 自己建的软链**:随时可以卸载、重装
- **真实目录**:永不覆盖,安装直接拒绝——你的手工数据不可能被应用冲掉
- **别人的软链**:只在显式确认(Replace 弹窗)后替换
- **自动路径**:批量操作中遇到任何歧义一律跳过并标记,不做静默写入

## 删除的边界

- **卸载**:只删软链,来源文件不动
- **彻底删除**(卡片垃圾桶):先卸干净所有 Agent 的软链,再把技能目录移进废纸篓——可恢复
- **移除来源**:删索引和克隆缓存,已安装的软链保留(可选择一并清理)

## 更新为什么必须手动确认

软链直连意味着「拉取 = 立刻分发」。如果应用自动 pull,上游作者删改文件的行为会瞬间传导到你所有 Agent。所以设计上前置一道 git diff 预览,你看过变化、点确认,变更才落盘。这不是功能缺陷,是这个工具最重要的安全决定。
